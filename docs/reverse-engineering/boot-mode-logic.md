# 进入刷写模式的固件逻辑（逆向分析）

本页记录从反编译源码中还原出的「长按 HOME+X+Y 进入 USB 刷写模式」的
完整判定逻辑，供二次开发与安全研究参考。触发链已在 2026-10-04 逐字节
复核（含两条此前文档遗漏的条件）。

## 结论速览

- 触发代码在主循环 `0x01E106CA`~`0x01E10706`：满足全部条件并**连续
  保持约 133 个轮询周期（约 3 秒）**后跳转 `0x01E1347C`，调用
  `FUN_01e01d94` 进入下载模式；
- 判定共 **5 个条件**：两道运行时闸门（`0x608 != 0`、`0x607 == 0`）、
  **按键计数恰好为 3**（`FUN_01e0e2f6`）、`0x201 & 0x10 == 0`、
  `0x200 & 0x03 == 0x03`；
- **成功与否只看电脑是否枚举出 `BR23 UBOOT1.00`**。灯灭只是入口函数
  切断外设电源的动作，不能当作成功；
- 按住期间**不要碰摇杆、扳机或其他任何按键**——按键计数必须恰好
  等于 3，多一个少一个都会失败（见「条件③」）；
- 固件内**不存在**第二条进入下载模式的软件路径（附录 A），
  「远程进恢复模式」在现有固件上被正面排除；
- 改组合键的补丁必须**同步改按键计数门槛**，否则永远触发不了
  （2026-10-03 探针事故，见「探针事故记录」）。

## 触发链（逐字节核对）

反汇编（地址为 Ghidra 基址 `0x01E000C0`；`app.bin` 偏移 = 地址 − 0x01E000C0）：

```
01e106ca  lb.z r1,[r15 + 0x608]      ; 条件① 0x608 != 0
01e106d0  jz   r1,0x01e10704
01e106d2  lb.z r1,[r15 + 0x607]      ; 条件② 0x607 == 0
01e106d6  jne  r6,#0x3,0x01e10704    ; 条件③ 按键计数 == 3
01e106da  jnz  r1,0x01e10704
01e106dc  movz r1,#0x201
01e106e0  lb.z r1,[r15 + r1]
01e106e4  jmnz r1,#0x10,0x01e10704   ; 条件④ 0x201 bit4 == 0
01e106e8  movz r1,#0x200
01e106ec  lb.z r1,[r15 + r1]
01e106f0  and  r1,r1,#0xffffff03
01e106f4  jne  r1,#0x3,0x01e10704    ; 条件⑤ 0x200 低 2 位 == 11b
01e106f8  lh.z r0,[r15 + 0xee]       ; 按住计时器
01e106fc  jae  r0,#0x85,0x01e1347c   ; ≥0x85 → 进入
01e10702  add  r0,#0x1
01e10704  sh   r0,[r15 + 0xee]
...
01e1347c  add  r0,r10,#0x5fc
01e13480  call 0x01e367de            ; 状态保存
01e13484  call 0x01e01d94            ; >>> 进下载模式，不返回 <<<
01e13488  goto 0x01e13488
```

任一条件不满足 → 跳 `0x01E10704`，把 `r0=0` 写回计时器（清零重计）。

### 条件① / ②：两道运行时闸门（含义未定）

`0x607`、`0x608`（上下文偏移）全固件**只有读、没有立即数写**，
疑似由运行时状态或设置区派生。2026-10-03 事故（设置区被抹）后，
连出厂组合键都无法触发，怀疑与这两道闸门有关（待实机确认）。

### 条件③：按键计数（`FUN_01e0e2f6`）

- `r6` 来自主循环顶部的 `call 0x01e0e2f6`（`0x01E1039E`）：
  对 `ctx[0x200..0x203]` 四个字节做 **popcount**（按半字节查表
  `0x01E1B65D` 累加），并把 `0x201` bit1 从计数中屏蔽；
- 结果必须**恰好等于 3**——即按住期间位图里只能有 3 个按键位；
- 出厂组合 HOME+X+Y 恰好 3 个键位 → 通过；多按任何一个键、
  甚至摇杆/扳机产生额外位 → 计数 >3 → 永远进不去。

### 条件④ / ⑤：组合键位

- `0x201` bit4 是冲突保护位，必须为 0（该键按下时本组合失效）；
- `0x200` 低 2 位同时为 1。位与物理按键的完整对应关系尚未逐一
  确认；出厂组合 HOME+X+Y 满足此条件。

### 计时与入口

- 计时器 `ctx+0xEE`：条件满足每轮 +1，任一失败清零；`>= 0x85`
  （133 个轮询周期 ≈ 3 秒）跳转入口；
- 入口 `0x01E1347C` 先保存状态（`0x01E367DE`），再调用
  `FUN_01e01d94`：

```c
void FUN_01e01d94(void)
{
  func_0x021127f0(2);          // 切外设/LED 电源（灯因此熄灭）
  func_0x02000114(0xaf, 0xff); // 系统控制寄存器写 0xAF=0xFF
  *(volatile unsigned *)0x1E0000 |= 0x10;  // 置「下次复位进 UBOOT」记忆位
  for (;;) { }                 // 死循环等复位
}
```

随后片上逻辑/看门狗复位，芯片从 MaskROM 启动
**UBOOT1.00**（SCSI 大容量存储设备，`VID_4C4A / PID_2342`，
inquiry 字符串 `BR23`）。

> 「灯灭 ≠ 成功」：灯灭发生在入口函数执行的第一步（切断电源），
> 与复位后是否成功进入 ROM 无关；只有电脑端出现
> `BR23 UBOOT1.00` 才是进入成功。等待 1~10 秒都正常。

## 探针事故记录（2026-10-03 ~ 04）

背景：为确认 B 键位图位，构建了 `patches/mode-b-probe.py` 探针固件并
刷入（`build/probe-full.bin`）。字节级复盘（出厂 vs 探针，app.bin）：

| 偏移 | 出厂 | 探针 | 含义 |
|------|------|------|------|
| `0x10632` | `FC` | `FA` | `and` 取反掩码：keep 0x03→0x05（bit0+bit2） |
| `0x10637` | `06` | `0A` | `jne` 立即数：keep 3→5 |

**问题 1：条件③未同步。** `0x10616`（`jne r6,#0x3`）没有改，探针
仍要求按键计数 == 3；按 HOME+B 只有 2 个键，永远凑不满 → 组合键
失效。

**问题 2：设置区被抹。** 当时刷的是 1MB 全片镜像，设置区
（`0xF6000` 起）全为 FF（0 个非 FF 字节），校准/模式设置被清 →
LED 全灭、模式异常，很可能同时让条件① ② 不再成立（连出厂
HOME+X+Y 也无法触发）。

教训（现已写入工具与补丁脚本的防呆检查）：

1. **改组合键必须同步条件③**（按键计数门槛 = 新组合的键数）；
2. **只刷 0x53000 小镜像**；确需 1MB 全片时，用
   `--settings <本机备份>` 合并设置区后再刷；
3. 刷前必须备份（GUI 第 2 项 / `python -m mico backup`）。

## 恢复路径

1. **软件**：进入刷写模式（看到 `BR23`）→ 写回备份
   （GUI「4. 恢复备份」/ `python -m mico flash backup.bin`）。
2. **进不去刷写模式时（本事故的状态）**：走硬件手段，见附录 B。

## 附录 A：是否存在远程进恢复模式的通道？

静态结论：**没有**。

- 全固件只有**一处**写「下载记忆位」（`0x1E0000` 位 4）：
  `0x01E01DA6`，位于 `FUN_01e01d94` 内；而 `FUN_01e01d94` 的
  唯一调用者就是组合键触发链的入口 `0x01E1347C`；
- 主机→手柄的私有 HID 命令通道（`FUN_01e06ce0`，魔数 `"GHC\0"`，
  子命令 0..5）里没有任何调用下载模式入口的分支；5 个子命令都是
  蓝牙/音频重载一类的动作；
- 固件字符串中不存在升级/OTA/恢复相关的命令词。

因此，「远程把设备踢进恢复模式」在现有固件里被正面排除：
只有组合键（本页）或硬件手段（附录 B）。

## 附录 B：进不去刷写模式时的硬件手段

- **USB_KEY**：芯片启动瞬间在 USB 总线上连续发送 16 位键 `0x16EF`
  （D- 当 CLK、D+ 当 DATA），收到芯片 ACK（D+/D- 同时拉低 1~2 ms）后
  正常接主机即可进入下载模式——这是杰理官方升级器（dongle）的原理；
  波形与实现见 kagaimiq/jl-uboot-tool 的 `docs/how-to-enter-uboot.md`
  （本仓库外）；
- **ISP_KEY**：用 ISP 协议上传专用 payload 让芯片直接进 BootROM
  （较新芯片支持）；
- **擦空闪存让启动失败**：闪存无有效固件时芯片开机自动进入下载
  模式（拆壳断开/擦除闪存即可）。

## 相关地址速查

| 项 | 值 |
|----|-----|
| 触发判定段 | `0x01E106CA` ~ `0x01E10706` |
| 入口 | `0x01E1347C` → `FUN_01e01d94`（app.bin `0x1CD4`） |
| 按键计数函数 | `FUN_01e0e2f6`（app.bin `0xE236`；半字节表 `0x01E1B65D`） |
| 计数输入 | `ctx+0x200..0x203`（`0x201` bit1 屏蔽） |
| 计时器 | `ctx+0xEE`，阈值 `0x85`（≈3 秒，133 周期） |
| 闸门 | `ctx+0x608 != 0`、`ctx+0x607 == 0` |
| 下载记忆位 | `0x1E0000` 位 4（只写一处：`0x01E01DA6`） |
| 闪存偏移换算 | `offset = addr − 0x01E000C0` |

> 本文档 2026-10-04 修正：旧版把 `r6 == 3` 误读为「1 号灯 / 灯效
> 状态机」，实际是**按键计数**（popcount）；并补充条件① ②
> （两道运行时闸门）与「灯灭 ≠ 成功」警示。
