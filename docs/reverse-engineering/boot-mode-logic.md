# 进入刷写模式的固件逻辑（逆向分析）

本页记录从反编译源码中还原出的「长按 HOME+X+Y 进入 USB 刷写模式」的
完整判定逻辑，供二次开发与安全研究参考。

## 触发函数

反编译结果中的 `FUN_01e01d94`：

```c
void FUN_01e01d94(void)
{
  func_0x021127f0(2);          // 首先切断外设/LED 相关电源（灯因此熄灭）
  func_0x02000114(0xaf, 0xff); // 写系统控制寄存器 0xAF=0xFF：请求进入下载模式
  do {
                    /* 死循环，等待复位进入 ROM 的 UBOOT1.00 */
  } while( true );
}
```

关键点（结合既有分析与实物验证）：

- `func_0x02000114(0xaf, 0xff)` 访问的是 `0x1E0000` 总线页内的控制寄存器
  （偏移 `0xAF`），写 `0xFF` 相当于置位「下次复位进入 USB 下载模式」的
  记忆位（此前分析标注为 **0x1E0000 页 bit4**）；
- `func_0x021127f0(2)` 先行切断灯效电源，所以**手柄灯会先熄灭**；
- 随后死循环，等待片上逻辑/看门狗复位进入 MaskROM 的 UBOOT1.00。

这解释了实物现象：**长按成功后灯先灭，随即电脑出现 `BR23 UBOOT1.00`**。

## 判定条件

在按键扫描主循环中，有一段逻辑（整理自反编译代码）：

```c
if (1号灯模式 /* iVar11 == 3 */ &&   // 有线模式指示灯状态
    组合键_释放标志 == 0 &&           // 0x607 == 0
    0x201 按键位图 & 0x10 == 0 &&     // 排除冲突键
    (0x200 按键位图 & 3) == 3)        // HOME(bit0) + X/Y(bit1) 组合
{
    if (*(ushort*)(ctx + 0xEE) > 0x84)   // 计数器 > 132 个周期
    {
        FUN_01e367de(ctx + 0x5FC);       // 状态保存/外设收尾（作用为推断）
        FUN_01e01d94();                  // >>> 进入刷写模式 <<<
        // 永不返回
    }
    *(ushort*)(ctx + 0xEE) += 1;         // 计时
}
```

要点：

1. **必须是 1 号灯（有线模式）**——蓝牙模式下不会进入刷写；
2. **按键位图**：`0x200` 的低 2 位表示 HOME + (X/Y) 组合；
   `0x201 & 0x10` 是冲突保护（防止误触）；
3. **计时阈值 `0x84 = 132`**：按住期间每轮询周期累加，大约等于 3 秒
   （轮询周期约 22~24 ms）；
4. 松手或任一条件不满足 → 计数器清零（代码中 `sVar39 = 0` 各分支）。

## 按键位图（0x200 / 0x201）

结合反编译中的位运算：

| 偏移 | 位 | 含义 |
|------|-----|------|
| 0x200 | bit0 | HOME |
| 0x200 | bit1 | X 或 Y 组合键（与本手柄布局有关） |
| 0x201 | bit4 | 组合键冲突标志（按下时为 0 才有效） |

## 进入刷写模式后的 USB 行为

- 芯片复位进入 **MaskROM 的 UBOOT1.00**；
- 以 SCSI 大容量存储设备出现：**`VID_4C4A / PID_2342`**，
  inquiry 字符串 `BR23` / `UBOOT1.00`；
- 只支持读写内存 + 执行代码（裸机命令）；
- 刷写工具先传 RAM loader（`mico/data/br23loader.bin`，MengLi 加密），
  再跳转执行，之后才能读写闪存。
