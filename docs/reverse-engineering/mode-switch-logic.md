# 模式切换逻辑（Mode 组合键）与 Mode+B 可行性

本页记录固件中「模式切换」相关代码的逆向结论，用于评估把
**Mode+B** 分配给「Vibe Coding 模式」的可行性。

代码地址均为 Ghidra 反编译地址（基址 `0x01E000C0`）。换算规则：

```
app.bin 偏移 = 地址 - 0x01E000C0        # 仅对代码区/常量区成立
镜像内偏移   = 0x030E0 + app.bin 偏移   # 密文，见 flash-layout.md
```

> ⚠️ 固件在 RAM 低地址（`0x4130`、`0x6C06`、`0x70A9`、`0x7978` 一带）
> 还有一批**运行时表**。这些是芯片内部 RAM，**不是** `app.bin` 的文件
> 偏移，也不是镜像里的位置：文件里同偏移处的字节与这些表无关。
> 下文凡 RAM 表都用「RAM `0xXXXX`」标注。

## 0. 结论速览

| 结论 | 依据 |
|------|------|
| 「当前模式」是 RAM `0x4130` 的一个字节 | 全固件按 `DAT_00004130` 分支（USB/蓝牙/描述符） |
| 模式记录表在 RAM `0x7978` 起、步长 `0x20` | `FUN_01e02f7e`（`01E02F7E`）写入；`FUN_01e001a0` 读取 |
| 模式切换 = 组合键长按约 200 个扫描周期 | `FUN_01e092bc` 掩码判定 + 计数器 `ctx+0xE8/0xEC` |
| 切换动作会重建蓝牙协议栈 | 触发路径调用 `FUN_01e030e6` + `FUN_01e03108` |
| 官方手册只定义 Mode+A / Mode+X / Mode+Y | `_docx_text.txt`（刷机版说明书） |
| **Mode+B 未出现在任何掩码分支** | 反汇编 `0x01e092bc`~`0x01e10af4` 全段核过 |
| B 键在按键位图中的确切位**尚未实机确认** | 见 §4.1 探针方法；探针必须同步按键计数门槛 |

## 1. 模式号与模式表

### 1.1 当前模式字节 RAM `0x4130`

`DAT_00004130` 是「当前模式」选择字节。代码里出现过的取值与分支：

- `DAT_00004130 == 8`：走 USB 路径（`FUN_01e07ab4` 一带）；
- `DAT_00004130 == 9`：另一套 UI（`FUN_01e0a0d4` 一带）；
- `(DAT_00004130 < 8) && (1 << mode & 0x92)`：mode 1/4/7 的 LED/震动分支；
- `DAT_00004130 - 1 < 9`：合法模式号范围 1..9（`FUN_01e0a0d4` 等）。

即**模式号取值 1..9**；`FUN_01e05688` 里还会按传输类型直接赋值：

```c
if (DAT_00006bc1 == 2) {
    if (DAT_00006bc4 == 1)      DAT_00004130 = 7;   // 接收器 / NS?
    else if (DAT_00006bc4 == 3) DAT_00004130 = 3;   // XInput?
    else if (DAT_00006bc4 == 4) DAT_00004130 = 2;   // 安卓?
} else if (DAT_00006bc1 == 1) { DAT_00004130 = 5; } // 蓝牙?
else if (DAT_00006bc1 == 0)   { DAT_00004130 = 9; } // USB?
```

具体数值与「NS / XInput / 安卓」的对应关系以实测为准（与手册
Mode+Y=NS、Mode+X=XInput、Mode+A=安卓 的顺序基本一致，但差值有待
确认）。

### 1.2 模式记录表（RAM）

写入函数 `FUN_01e02f7e`（`01E02F7E`）：

```c
void FUN_01e02f7e(undefined1 param_1)      // param_1 = 模式号
{
  _DAT_00007978 = 0x55aa;                    // 表项标记（u16）
  DAT_0000797b = param_1;                    // 表项首字节 = 模式号
  func_0x021127a8(0x797c, &DAT_00004160, 6); // 当前 6 字节参数存回表项
}
```

读取函数 `FUN_01e001a0`（`01E001A0`，app.bin `0x00E0`）：

```c
void FUN_01e001a0(uint param_1)              // param_1 = 表索引
{
  if (_DAT_0000688c == 0x85) {
    DAT_00006a58 = 1;
    if ((&DAT_00006c06)[param_1] != '\0') {          // 可用性标志表
      DAT_00004130 = (&DAT_0000797b)[param_1 * 0x20];      // 模式号
      func_0x021127a8(&DAT_00004160, param_1 * 0x20 + 0x797c, 6); // 参数
      return;
    }
    DAT_00004130 = 5;                                 // 索引不可用 → 默认
    ...
  } else if (_DAT_0000688c == 200) { ... }
}
```

所以一条记录的布局是：

| 偏移 | 含义 |
|------|------|
| `+0x00` | u16 标记 `0x55AA`（`0x7978`） |
| `+0x03` | 模式号字节（`0x797B`） |
| `+0x04` | 6 字节参数（`0x797C`）→ 切换时拷进 RAM `0x4160` |
| 步长 | `0x20` |

配套还有两处 RAM 表：`(&DAT_00006c06)[idx]`（可用性标志）与
`*(u16*)(mode * 0x20 + 0x70a9)`（`FUN_01e05688` 读取的 u16 参数）。

### 1.3 清表函数 `FUN_01e0e340`

```c
void FUN_01e0e340(int param_1)
{
  _DAT_00007978 = 0;                                  // 表标记清 0
  *(undefined2 *)(&DAT_00007978 + param_1 * 0x20) = 0;
  FUN_01e3780a(0x24, 0x140);                          // 通知协议栈
  DAT_00006c06 = 0;                                   // 可用性清位
  (&DAT_00006c06)[param_1] = 0;
}
```

组合键处理里会一次性清 0/3/7/2/5 五个索引，再重新装载目标模式
（`0x01e1045e`~`0x01e1047a`、`0x01e105dc`~`0x01e105f8`）。

## 2. 组合键判定（`FUN_01e092bc`，app.bin `0x91FC`）

按键状态不是「每个键一段代码」，而是**一张位图**：`ctx+0x200` 起
4 个字节（`0x200`/`0x201`/`0x202`/`0x203`）。组合键全部写成
「读 `ctx+0x201` / `ctx+0x200`，与掩码比较」。

反汇编原句（`0x01e103c6`~`0x01e10588`，逐字节核对）：

```
01e103c6  movz r0,#0x201
01e103ca  lb.z r0,[r15 + r0]
01e103ce  and r1,r0,#0xffffff31
01e103d2  jne r1,#0x31,0x01e104be      ; (0x201 & 0x31) == 0x31 → 分支
01e103d6  lh.z r0,[r15 + 0xe8]          ; 计数器 +1
...
01e1041c  movz r0,#0x201
01e10424  and r0,r0,#0xffffff30
01e10428  jne r0,#0x30,...              ; (0x201 & 0x30) == 0x30
...
01e104be  and r1,r0,#0xffffff32
01e104c2  jne r1,#0x32,...              ; (0x201 & 0x32) == 0x32
...
01e10584  and r0,r0,#0xffffff1c
01e10588  jne r0,#0x1c,...              ; (0x201 & 0x1c) == 0x1c
...
01e10568  movz r0,#0x201
01e1056c  lb.z r0,[r15 + r0]
01e10570  jmnz r0,#0x11,0x01e10688      ; (0x201 & 0x11) != 0
```

对应 C 里出现过的掩码组合（全部在 `0x201` 上）：
`0x11`、`0x15`、`0x14`、`0x10`、`0x04`、`0x31`、`0x32`、`0x30`、`0x1c`。

已知语义（对照手册行为）：

- `(0x201 & 0x31) == 0x31`：长按 ≥200 周期 → `ctx+0x2d = 10`、
  `ctx+0x298 = 1`（模式切换流程，计数器 `ctx+0xE8 > 200`）；
- `(0x201 & 0x32) == 0x32`：长按 ≥0xC9（201）周期 → 同族分支；
- `(0x201 & 0x1c) == 0x1c`：长按 ≥0xC9 → 复位/恢复灯效状态；
- `(0x201 & 0x11) != 0`：长按 ≥200 → `ctx+0x2e = 4` +
  `FUN_01e030e6()` + `FUN_01e03108()`（蓝牙栈重载）——强制切模式；
- `(0x201 & 0x14) == 0`、`(0x201 & 0x15) == 0` 等是**排除条件**：
  只有这些位都没按下，才允许进入某些路径。

> 注意：`0x201` 的位与物理按键的对应关系尚未逐一确认。
> 目前只能确认：这些位就是模式组合判定读取的唯一来源。

### 2.1 刷写模式入口（顺带核对，与 boot-mode-logic.md 一致）

```
01e106dc  movz r1,#0x201
01e106e4  jmnz r1,#0x10,0x01e10704   ; 0x201 & 0x10 != 0 → 跳过（冲突保护）
01e106e8  movz r1,#0x200
01e106f0  and r1,r1,#0xffffff03
01e106f4  jne r1,#0x3,0x01e10704     ; (0x200 & 3) != 3 → 跳过
01e106f8  lh.z r0,[r15 + 0xee]
01e106fc  jae r0,#0x85,0x01e1347c    ; 计时 ≥0x85 → 刷写
...
01e1347c  add r0,r10,#0x5fc
01e13480  call 0x01e367de            ; 状态保存
01e13484  call 0x01e01d94            ; >>> 进刷写模式，不返回 <<<
01e13488  goto 0x01e13488
```

> **2026-10-04 修正**：触发链还有两个此前遗漏的条件——运行时闸门
> `0x608 != 0` / `0x607 == 0`，以及**按键计数恰好为 3**
> （`FUN_01e0e2f6` 的 popcount，`0x01e106d6` 的 `jne r6,#0x3`）。
> 完整 5 条件与逐字节反汇编见
> [boot-mode-logic.md](boot-mode-logic.md)「触发链」。

- 组合键 = `ctx+0x200` 低两位同时为 1（手册称 HOME+X+Y，整机实测
  约 3 秒成功）；
- `ctx+0x201 & 0x10` 必须为 **0**（防止与另一键冲突）；
- 按键计数必须**恰好 3**：按住期间不要碰摇杆、扳机或其他任何键；
- 计时器 `ctx+0xEE` 阈值 `0x85`（≈133 个轮询周期 ≈3 秒）。

## 3. Mode+B 的插入点（不改动其他模式）

官方手册只列出三种强制组合：

```
长按 设置键 + A  → 安卓模式
长按 设置键 + X  → XInput 模式
长按 设置键 + Y  → NS 模式
```

`0x201` 的组合掩码里**没有任何「多出来的裸 B 组合」**（见 §2 清单），
所以 Mode+B 在现有固件里是空档，可以安全占用。

落地三步（按风险从低到高）：

1. **新增模式记录**：在模式表（RAM `0x7978` 起，步长 `0x20`）里增加
   一条记录：标记 `0x55AA`、模式号字节 = 新模式号（1..9 里挑未用的，
   例如复用 6 或 7 之外的号）、随后 6 字节参数从现有模式拷一份改；
   同时把可用性标志 `0x6C06 + idx` 置非 0。
   —— 这一步在代码里对应 `FUN_01e02f7e` 的写入逻辑与
   `FUN_01e001a0` 的读取逻辑，做成补丁时直接照抄现成记录。
2. **新增组合键分支**：在 `FUN_01e092bc` 的掩码判断处增加
   「Mode + B」分支（仿照 `(0x201 & 0x11)` 分支：计数器到阈值 →
   调用 `FUN_01e030e6()` + `FUN_01e03108()` 重载，并用新索引调用
   `FUN_01e001a0(新索引)`）。
3. **挂键盘描述符集**：Vibe Coding 模式切换到内置键盘 HID 模板
   （`app.bin` 偏移 `0x21407`，报告 ID 1；见
   [vibe-coding-mode.md](../development/vibe-coding-mode.md)），
   按 `ctx+0x200` 位图填 6 个按键槽。

> **前置条件**：第 2 步需要知道 B 键在 `ctx+0x200/0x201` 里的确切位。
> 这一点目前**没有静态结论**，必须先在实机上确认（下一节）。

## 4. 按键位图与 B 键位（待实机确认）

- 位图：`ctx+0x200` ~ `ctx+0x203`，由 ADC 扫描路径合并写入
  （相关表：RAM `0x1E1E3DC`，24 条 `(offset<<8)|mask`，负责把逻辑
  键位映射到位图；另有 `0x1E1E40C` 掩码表）；
- 重映射表覆盖：`0x200` 全部 8 位、`0x202` 全部 8 位、`0x201` 的
  bit0/1/2/3/6/7、`0x203` 的 bit4/5（共 24 条）。B 键一定在这些位
  里，但表里只有「位」，没有名字，**静态分析给不出“哪一位是 B”**；
- 组合键判定**已用到**的位：`0x200` 的 bit0/bit1（刷写组合）、
  bit2/bit3（另两条分支），`0x201` 的 bit0/1/2/3/4/5；
- B 键候选位（按建议顺序，详见 §4.1 表）：先试 `0x200` 的
  bit2 → bit5 → bit4 → bit6 → bit3；再试 `0x202`/`0x201`/`0x203` 的
  单键位。其中 `0x200` bit2 在反汇编里有一个独立分发
  （`0x01e1077c` `jmnz r0,#0x4`），值得优先试。

### 4.1 确认方法（探针）

思路：不动模式逻辑，只把「刷写模式触发条件」临时换成候选位——按住
候选组合约 3 秒，能进刷写模式就说明候选命中。

**探针有一条硬性要求：必须同步改按键计数门槛。** 触发链的条件③要求
`ctx[0x200..0x203]` 的 popcount **恰好等于 3**（见
[boot-mode-logic.md](boot-mode-logic.md)）。候选若是 2 键组合，位图计数
只有 2，条件③永远失败——2026-10-03 的第一版探针就栽在这里（详见
boot-mode-logic.md「探针事故记录」）。

`patches/mode-b-probe.py` 一次只探一个候选 `(位图字节, 掩码)`，重写
四条**等长**指令（app.bin 偏移 `0x10616` 与 `0x01E106E8` 起）：

| 偏移 | 出厂指令 | 探针写入 |
|------|----------|----------|
| `0x10616` | `86 f8 15 06` `jne r6,#0x3,...` | 计数门槛改为候选键数，2 键 → `86 f8 15 04` |
| `0x10628` | `41 e0 00 02` `movz r1,#0x200` | 候选字节，如 `41 e0 01 02` = `#0x201` |
| `0x10630` | `71 e1 fc 10` `and r1,r1,#0xffffff03` | `71 e1 (~掩码&0xFF) 10` |
| `0x10634` | `81 f8 06 06` `jne r1,#0x3,...` | `81 f8 06 (掩码<<1)` |

两条编码规则是对全固件样本反推并逐条核对的，可直接复用：

- `and rD,rS,#0xffffffXX`（4 字节）＝ `[0x70|D, 0xE1, (~XX)&0xFF, S<<4]`
  —— 128 处样本全部吻合（另有 15 处 `0xF1` 变体，语义待定，暂不用）；
- `jne rD,#imm,目标`（4 字节）＝ `[0x80|D, 0xF8, (Δ/2)&0xFF, ((imm&0x7F)<<1)|符号]`，
  `Δ = 目标 − (地址+4)` —— 351 处样本全部吻合。同长度改写时 Δ 不变，
  所以 `0x10616` 第三个字节恒为 `0x15`、`0x10634` 恒为 `0x06`。

三个硬限制（脚本里已有校验）：

- 掩码必须 `1..0x7F`：`jne` 的立即数是 **7 位**（最大样本 `0x75`），
  bit7 候选要另配指令才能探；
- `0x201` bit4（掩码 `0x10`）是刷写组合的**冲突保护位**
  （`0x01e106e4` 的 `jmnz r1,#0x10`），不能当候选；
- `0x201` bit1 在按键计数里被屏蔽（`0x01e1b810` 表），按下去计数为 0，
  配不出合法门槛——不要当候选。

操作步骤：

1. 备份当前固件（GUI 第 2 项 / `python -m mico backup out.bin`）；
2. 在 `patches/mode-b-probe.py` 里改一个候选（只改 `CANDIDATE`，
   计数门槛由脚本按掩码位数自动同步）；
3. 构建探针镜像——**不要加 `--full`**（见下方事故警示）：
   `python tools/build_firmware.py --patch patches/mode-b-probe.py --out build/probe.bin`
4. 从刷写模式刷入（GUI 第 5 项「刷入自选镜像」）；
5. 按住对应组合约 3 秒：**电脑出现 `BR23 UBOOT1.00`** → 命中，
   把 `(字节, 掩码)` 记到本页；灯灭只是入口动作，不等于成功；
6. 未命中：从备份还原，换下一个候选重复 2~5。

> ⚠️ 2026-10-03 事故：第一版探针用 `--full` 构建，1MB 全片镜像把设置区
> （`0xF6000` 起）抹成空白，手柄 LED 全灭、出厂组合键也进不去刷写模式。
> 探针只刷 0x53000 小镜像；确需全片时用 `--settings <本机备份>` 合并设置区。

建议顺序（掩码含 `0x200` 的 HOME 位 bit0 时按 HOME+候选键，其余字节
为单键 B；计数门槛由脚本自动同步为掩码位数）：

| 序 | 字节 | 掩码 | 按键组合 | 该位现状 |
|----|------|------|----------|----------|
| 1 | `0x200` | `0x05` | HOME + B（B=bit2） | bit2 有独立分发（`0x01e1077c`） |
| 2 | `0x200` | `0x21` | HOME + B（B=bit5） | 组合判定从未使用 |
| 3 | `0x200` | `0x11` | HOME + B（B=bit4） | 组合判定从未使用 |
| 4 | `0x200` | `0x41` | HOME + B（B=bit6） | 组合判定从未使用 |
| 5 | `0x200` | `0x09` | HOME + B（B=bit3） | bit3 被 `0x0d` 分支使用 |
| 6 | `0x202` | `0x01`~`0x40` | B 单键 | 0x202 全部 8 位都干净 |
| 7 | `0x201` | `0x40` | B 单键 | bit6 干净 |
| 8 | `0x203` | `0x10` / `0x20` | B 单键 | bit4/5 干净 |
| 9 | `0x201` | `0x02`/`0x04`/`0x08`/`0x01`/`0x20` | B 单键 | 已被其他分支用到 |
| 10 | `0x203` | `0x08` | B 单键 | bit3 被两条分支用到 |

> 注意：`0x200` bit0/bit1 与 HOME / X / Y 的逐键对应没有单独验证（只能
> 确定出厂刷写组合要求这两位同时为 1）。因此 `0x200` 的候选项要配合
> 不同按键逐次尝试：**HOME+B、X+B、Y+B 各按一次**，任一组触发即命中。

命中登记（实机确认后填写）：

| 日期 | 字节 | 掩码 | 结论 |
|------|------|------|------|
| —    | —    | —    | 待测 |

确认到 B 位之后，第 3 节的第 2 步才有确定的掩码可写；在此之前
